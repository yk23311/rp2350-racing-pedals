# 嘉立创EDA网络兼容导入候选包

2026-11-07。这个目录仍是**用于导入的KiCad格式兼容副本，不是已生成的EDA原生eprj/epro工程**。原始 `hardware/carrier` 和已经核验的Gerber包保持不变。

## 为什么另做这个包

用户导出的`eda-import-diff.csv`表明：221个实际连接的引脚，在当前EDA PCB中导入前均显示为未指定网络；49个GND引脚在原理图侧被PWR_FLAG命名；另有15处元件值回填差异。原始KiCad10板图使用新版具名网络语法，旧式索引语法是本次兼容候选的验证方向。只显示铜线/DRC条数减少，不能证明网络导入成功。

## 副本中的兼容处理

- 所有844处网络关联写为旧式数字索引，补齐网络表；pad保留索引和原网名，segment/via/铜区引用索引，铜区增加net_name。**文件版本没有伪改为旧版。**
- 每个封装的Reference/Value属性使用兼容fp_text形式表达，保留各自数值、坐标、字体、隐藏状态和UUID。
- 仅移除原理图ERC专用PWR_FLAG及其独立标记支线/标签，从而避免EDA把这个声明当作地网名称；模块GND引脚的ERC类型从power_in调整为power_out，承担原来的供电声明，实体连接不变。本地模块符号库同步此纯ERC元数据变化。
- 581段走线、27个过孔、72个元件、238个焊盘、安装孔/禁布区和其他PCB几何均保留。

## 已完成的验证

- 原生KiCad读回全部元件/焊盘/走线/过孔，与原件逐项比较，几何/网络/实际值一致。
- 原生ERC：0违规；DRC：0违规、0未连接、0原理图一致性问题，使用同一原规则配置。
- 原生导出的原理图网表和原72元件电气模型逐脚一致。
- 九层Gerber的完整绘图流与原版完全一致；PTH/NPTH钻孔指令与原版一致。
- Python全套130项测试通过，其中6项为新增兼容合同测试。
- 独立复核反向还原全部PCB变换后，其完整S表达式结构与原版一致；符号/原理图只存在上述声明变化。

报告保存在`reports/`；诊断源报告UTF-16、制表符分隔，虽然后缀为CSV，不能按普通逗号CSV解析。

## 用户手动验证步骤

1. 在EDA专业版开始页选“导入KiCad”，选择`carrier-net-compat.zip`，导入为新工程。
2. 首次先查看PCB，不执行“导入更新”或重建铺铜。任选有连接的焊盘，查看网络属性是否已正确获得名字，例如C1.1为ADC_THROTTLE、C1.2为GND（显示时可能带层级前缀），R25应为4.7k、C7应为4.7µF。
3. 运行DRC并保留结果。如果仍有网表差异，只查看/导出差异报告，不盲目应用；报告中221项网络都从未指定开始的情况应先排除。
4. 确认原生网络已经保留后，再按实际错误匹配最小孔径0.30mm规则，并验证重建铺铜后铜线和连接状态仍保留。
