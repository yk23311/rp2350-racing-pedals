# 07 校准拒绝导致界面断开：步骤与交接

日期：2026-10-31。

## 现场反馈与调查

用户此前反馈GP26一路测试正常，随后反馈点击完成校准时断开。错误原文和松开/踩到底原始值尚未取得，用户随后反馈“没事了，现在好了”。因此不将现场问题确定为USB物理断连或ADC跨度不足。

代码调查确认一个可独立复现的问题：固件拒绝CAL END或SAVE后返回完整ERR响应，Client将其抛为通用ProtocolError，GUI捕获所有异常后关闭串口。端点跨度小于128、没有对应校准会话等正常拒绝都会触发这个问题。

## 步骤报告

1. 追踪GUI完成按钮→Client.request→固件CAL END→异常处理。
2. 使用实际Tk按钮和Client解析器、模拟串口重现：校准拒绝后再次点击完成、保存拒绝后再次保存均无法发送第二次命令；新增两项回归测试先失败。超时关闭测试通过。
3. 完整ERR响应使用CommandRejected类型（保留ProtocolError继承兼容CLI）。GUI仅针对设备明确拒绝保留连接，读取最新状态后给出校准/保存提示；超时或损坏报文仍关闭连接。
4. 拒绝提示保留到下一次成功操作，避免后台轮询覆盖说明。
5. 执行 `.venv/Scripts/python.exe -m unittest discover -s tests -p 'test_*.py' -v`：17/17通过，包括新增3项GUI串口回归。固件未更改，无需重建或重新烧录。

## 交接报告

当前用户已报告现场恢复正常。现有调参窗口使用启动时载入的旧代码，更新在关闭并重新启动GUI后生效；板端参数不会因关闭GUI自动保存。

校准结束后松开踏板等待输出归零，显式保存到Flash。若未来再次出现拒绝，新GUI会提示缺少校准会话或端点变化不足的检查方向，仍需结合原始值判断。未读取或控制用户实际串口，未把模拟回归记为硬件测试。
