# 控制中心：按键测试、震动测试、一键升级

日期：2026-11-05。基于现有 PySide6 GUI、单串口工作线程与本地 0.4.1 震动转发修复。

## 界面与范围

保留现有四页，增加“设备测试”和“固件升级”页。所有功能不依赖 Steam 映射或电脑端虚拟手柄。沿用现有自动串口发现、断线状态和现代深色界面。

按键测试读取接收器原始输入，显示十四个实体手柄按钮的当前状态以及本轮是否观察到完整的按下和松开；支持清空记录。断线或数据过期显示不可用，不把丢包当作松开，不向游戏注入虚构按钮。摇杆、LT/RT 沿用实时显示。

震动测试提供左右马达 0–100% 强度和 100–3000ms 时长，默认 25%、500ms，启动和立即停止。板端执行截止时间，GUI 退出或串口断开也会到时停止；USB/接收器失联沿用优先停止和重试限制。测试中游戏震动不覆盖测试，结束后只接受新的游戏命令。展示转发状态、计数与故障；USB OUT 成功不等于无线手柄马达已转动。

## 升级流程

用户选择本项目桥接版 UF2 并点击升级。先完整检查 512 字节块、魔数、RP2350 ARM-S 家族 ID、块序号/总数、地址和重叠；禁止写入配置保留区 0x101FE000–0x10200000。不执行整片擦除。

新固件公布升级能力，接到串口 BOOTSEL 命令后停止震动、释放输出，发送确认后延迟进入 RP2350 ROM USB 下载模式。升级器关闭串口，等待本次新出现的 RP2350 下载盘，唯一匹配才写入；已有下载盘或多个新盘不自动选择。界面显示校验、等待磁盘、写入、等待重连、恢复连接各阶段。成功依据传输完成并重新读取到目标串口设备状态；显示板卡实际版本，不声称已做逐字节 Flash 回读。

旧固件没有 BOOTSEL 命令时说明首次手动操作，并提供显式“已手动进入下载模式，开始写入”入口。此入口同样只选择唯一 RP2350 下载盘，其他型号或多个匹配时拒绝。升级期间暂停调参和测试；未应用草稿不自动保存，重连后重读设备。关闭窗口在写入前可取消，写入阶段等待完成。失败保留清晰原因与 BOOT 恢复步骤。

## 实现边界

- 串口操作仍只由 Session 工作线程持有；升级过程不另开一个争用串口的连接。
- UF2 校验和磁盘发现/写入在独立模块中，IO 可注入以便模拟多板、盘符消失与失败。
- 震动测试和 BOOTSEL 命令使用严格范围和完整语法验证。
- 新版本暂定 0.5.0，包含本地尚未发布的 0.4.1 震动修复。构建交付，不擅自烧录或覆盖 GitHub 旧 Release。

## 验证与交接

先添加有意义的失败测试，再实现：按键过期/断线不误判、震动超时和停止优先、非法 UF2/越界/多盘拒绝、升级时无配置重放、旧固件提示和重连。运行完整 C/Python 测试、普通/诊断固件构建、GUI 离屏截图检查；生成步骤报告和 HANDOFF。实机震动、ROM 下载盘和游戏验收由用户执行并记录，不能以模拟测试代替。

## 方案取舍

推荐板端限时测试和 ROM 下载盘升级，沿用已有 USB/UF2 机制。仅 GUI 定时停震会在程序异常退出时失效；新增驻留引导器和串口直接写 Flash 会扩大擦写风险与维护范围，本次不采用。
