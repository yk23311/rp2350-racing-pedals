# RP2350 控制中心 GUI 与板端调参设计（用户已确认，已实施）

日期：2026-10-31。范围依据用户选择：状态可视化、踏板/手柄曲线与死区、手柄按键映射为其他手柄按键或键盘按键。不包含鼠标或宏。用户已回复“开始”；实现和验证见控制中心阶段报告。

## 目标与技术选择

推荐PySide6桌面GUI，保留pyserial与单线程串口工作队列；绘图使用QPainter自绘，避免浏览器服务或额外绘图库。Qt提供可缩放布局、绘图和高DPI支持，适合手柄图、曲线与实时仪表。旧Tk GUI保留为兼容入口。

其他路径：继续Tk成本低但视觉和复杂绘图维护成本更高；浏览器UI需要本地服务和桌面生命周期管理。此次选择原生桌面路径，不把输入映射搬到电脑端。

默认中文、深色仪表风格：石墨背景、青绿色油门、橙红色刹车，状态同时有文字和图标，不只依赖颜色。桌面初始约1280×800，支持缩放和滚动，避免高DPI下底部按钮被裁切。

## 页面与交互

1. 顶栏连接区：扫描并显示板卡串口、设备名与序列号；单一匹配板卡可自动连接，多台设备需要选择。刷新、断开、重连；拔出立即标为离线，旧数值变灰，不继续显示为实时。
2. 总览：油门/刹车大号百分比与动态图形；手柄外形、ABXY/方向键/肩键/摇杆按压亮起，双摇杆二维位置与LT/RT进度；Host接收器、报告新鲜度、armed及校准状态。
3. 踏板：输入行程/曲线后输出百分比、ADC与滤波值；γ/迟滞触发与释放/滤波窗口；曲线与实时游标；逐步校准操作。未校准时明确提示，不能把未知行程标成有效0%。
4. 手柄：左右摇杆死区与γ曲线、X/Y反向；左右扳机死区和γ曲线、实时百分比。摇杆用径向死区，γ作用于长度并保留方向，避免对角输入失真；输出限制合法范围，保留正负端点。
5. 按键：为14个标准数字按键（ABXY、方向键四向、LB/RB、Start/Back、L3/R3）选择保持默认、其他手柄按键、键盘按键或禁用。实时按下可高亮对应行。目标通过选择器设置，不全局捕获键盘。
6. 底部固定操作区：预览/未应用、RAM已应用、Flash已保存三个清晰状态；应用、撤销未应用编辑、保存到设备。滑块预览不会自动写固件或Flash。

## 数据来源与曲线语义

- 踏板原始/滤波/输出数据取自板端；手柄接收原始状态、处理后状态和最终合并输出分别标识，不能把Windows XInput最终状态标为真实手柄原始输入。
- GUI遥测目标20Hz，绘制可30Hz；串口IO不阻塞UI，队列合并重复轮询，命令优先。HID/ADC仍在板上约1ms循环，不跟随GUI刷新率。
- 仅根据VID/PID、序列号及协议握手识别本项目设备，不向不明串口发送探测命令。自动重连不重放设置、校准、SAVE或按键操作。
- 数据丢失时明确离线/过期。若接收器仍发送中立帧而无法区分无线手柄关机，则显示“接收器有数据”，不伪称无线链路在线。
- 保持MAX合并：手柄扳机曲线先作用于真实LT/RT，踏板曲线独立处理，随后各轴取较大值。用户能看到两路输入和最终结果。
- GUI预览与固件算法使用一致的定点参数、死区定义、量化及测试向量；拖动只是预览，点击应用才改变游戏输入。

## 板端映射与释放

- 映射全部由RP2350执行；关闭GUI后仍有效，电脑不做虚拟手柄/按键注入。
- 每次根据同一原始按钮快照生成目标集合，避免A→B、B→A级联。替换映射移除原始按钮输出，不额外保留一份。
- 按住源键时目标保持，松开释放；多源映射同一目标采用集合并集，只有所有源松开才释放。
- 使用现有键盘HID，普通键最多6个，修饰键单独位图；超限确定处理并提示，不允许粘键。这里只做单按键映射，组合宏/鼠标不在范围。
- 手柄模式可同时发XInput和映射键盘；旧键盘W/S模式继续保留，进入时停止游戏手柄映射并先释放旧输出。
- Host断连/超时、切换模式、应用映射或配置、校准、USB恢复时，先发手柄及键盘中立屏障，再按既有回中/释放条件恢复。新映射不直接继承按住的旧键。

## 协议与保存

- 新增有界的设备能力/Host遥测/手柄配置/映射查询及设置命令，使用独立短回复，不把所有数据塞进现有768字节GET。保留协议1踏板命令，旧工具仍可识别。
- 旧固件只支持踏板时，GUI显示其能力并禁用缺失手柄配置功能，明确提示需升级，不推测Host状态。
- 扩展配置记录使用新版本、有长度/CRC/序列号的统一记录，踏板校准与手柄设置一起双槽原子保存；读旧PDL1记录时在RAM迁移并保留校准，首次显式SAVE才写新格式。
- Flash仍在末尾两个4KiB扇区，记录可按整页扩展，所有擦写仍经过安全封装；掉电至少保留一份有效完整配置。
- 旧版固件无法读取新记录：实施前保留已读出的旧配置备份，升级说明明确降级行为，不能承诺旧UF2无损识别新配置。
- SAVE要求物理源按钮/扳机与踏板释放、USB在途及中立屏障满足条件；不能因某个按键被禁用而绕过保存释放条件。界面显示具体阻止原因。

## 分阶段交付与验收

1. 纯C曲线/映射/键盘合并与新配置迁移，测试边界、重复目标、断连释放、六键上限、掉电恢复。
2. 板端有界遥测/配置协议，测试旧GET兼容、截断、洪泛、超时、更新后的中立屏障；构建UF2，不自动烧录。
3. Qt桌面GUI：自动识别端口、异步遥测、仪表/手柄/曲线/映射编辑、清晰保存状态；用明确标注的演示数据测试离线布局，不冒充硬件数据。
4. PC测试与截图检查中文、高DPI、窗口缩小/滚动；所有既有C/Python回归继续通过。
5. 用户烧录后实测同帧转向+踏板、按键映射及释放、GUI关闭仍有效、SAVE重启保留、拔出回零、游戏验收。每阶段写步骤/交接报告并更新HANDOFF。
